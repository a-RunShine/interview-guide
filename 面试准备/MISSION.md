# Mission: 用 InterviewGuide 通过 Java 后端 / AI Agent 岗的项目轮面试

## Why

bojack 要以**项目经历**的形式，在 Java 后端 / AI Agent 岗面试中讲 InterviewGuide。
真实的成功标准不是"背下这个项目的知识点"，而是**在面试官的连续追问下不露馅、并且把追问变成加分项**——
拿到 offer，而不是在项目轮被打断。

## Success looks like

- 能用 60 秒讲清「这是什么项目 + 我的真实贡献边界 + 我理解到了什么深度」，且每一句都经得起追问
- 被问到"这块是你写的吗 / 为什么这么设计"，能给出**具体的类名、流程、取舍理由**，而不是"我们团队当时觉得……"
- 能从项目出发，主动把话头引向自己的强项（RAG 检索链路、Redis Stream 异步、LLM 接入抽象）
- 面对八股追问（虚拟线程、事务边界、消息队列选型、索引）能把答案锚回本项目的真实代码
- 〔**后期阶段**〕手上有 2–3 个自己真的做过的改动，能讲完整的「发现问题 → 定位 → 方案取舍 → 验证」故事线

## Constraints

- **零代码基础**：clone 后只跑通过一次测试，没有读过源码，没有做过任何改动。
- **时间**：每天约 1 小时。每课控制在 10 分钟内读完 + 5–10 分钟自测。
- **学习顺序（2026-09-15 明确，优先级高于课程规划）**：**先理解项目，理解到位之前不做任何改动。**
  bojack 的原话是「在理解之前我不想做贡献」——这是对的，没有上下文就无法做出自己的判断，
  照抄老师的结论在追问下会直接露底。因此「攒真实改动」从课程起点降级为**后期可选阶段**，
  由他本人在读懂之后自行决定是否启动。原定的第 2 课（恢复被禁用的测试）已挂起，材料保留备用。
- 沟通偏好：中文、结论先行、拒绝套话；先沟通计划再执行。
- 面试形式未定（可能是电话初筛 + 现场/视频深挖）。

## Out of scope（暂不追）

- 前端 React / TypeScript 细节 —— 目标岗位是后端与 Agent，前端只到"能说清架构分层"为止。
- WebRTC / 端到端语音模型的深度实现 —— 只在"已知问题与后续规划"层面能答即可。
- 从零手写一个同类项目 —— 目标是把现有项目讲透，不是重写。

## 关键风险（贯穿全课程）

项目来源是公开的开源仓库（`Snailclimb/interview-guide`，AGPL-3.0，作者为 JavaGuide 的 Snailclimb），
且 README 明示"可作为个人项目经历 / 毕设选题"——**面试官见过它的概率不低**。
因此全场唯一不能赌的事是：**可信度**。所有话术必须建立在真实做过的改动之上。
