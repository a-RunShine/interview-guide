# 学习顺序的修正：理解优先，贡献挂起

**bojack 在 2026-09-15 明确表态**：「让我先理解项目而不是做贡献吧……在理解之前我不想做贡献。」
这直接推翻了我在同一会话早些时候定下的课程顺序（先攒真实改动 → 再建骨架 → 再练表达）。

## 为什么他对我错

我当时把「先做改动」排在最前面，理由是面试可信度——没有真实改动，
「我的二次开发」这个框架就是空的。**风险判断没错，但解法错了：**

- 我给他的第一个任务（恢复 `VoiceInterviewServicePauseTest`）里，**最有价值的那一环是「判断」**
  ——为什么 commit 改了构造函数签名、注释为什么只提了一个依赖而实际缺三个。
  这一环只有真正读过模块、理解 `@RequiredArgsConstructor` 注入语义、知道项目测试规范的人才能做。
- 我在他零代码基础的情况下把结论直接喂给他，等于让他照抄。**这不是弹药，是换了包装的新空壳。**
  面试官追问「你为什么这么改」，他答不出自己推导的过程。
- 通用教训：**「制造经历」不能外包给老师。** 老师能做的是提供语境与反馈，经历必须是本人产生的。

## 已生效的调整

- 课程顺序改为 **理解 →（可选）动手 → 表达**；第 2 课（测试恢复）标记为**挂起**，材料保留。
- 第 3 课换成「跟一条真实请求走完全程」（简历上传 → Redis Stream 异步 → PDF），纯理解。
- 新增教学纪律：**在他自己提出问题之前，不主动给改动任务。**
  什么时候他自己说出「这里我觉得应该是 X，但代码写的是 Y」，那才是动手的时机。
- 第 1 课的**第二段逐字稿（讲自己的改动）继续留空**——在真正动手之前，他只能讲第一段和第三段。
  这个约束不能因为顺序调整而放松。

## 他的判断力基线（值得记录）

他在这两次交互里表现出的判断值得注意：
1. 被问「面试官最可能往哪个方向深挖」时，诚实回答「你觉得呢？我不知道我没面试过」——不装。
2. 主动要求先理解再动手，而不是接受我给的任务清单——**不盲从权威，且理由成立**。

→ 教学含义：他不是需要被推着走的类型，**给他地图和反馈比给任务清单更有效**。
后续课程应以「看懂什么、被问什么怎么答」为主，任务式作业只在必要时给。
